1.  THE MOST IMPORTANT RULE: DELTA, NOT ABSOLUTE
═══════════════════════════════════════════════════════════════════════════════

If you ever wire a signal from a higher layer back down to a lower layer,
feed the DELTA of that signal above its running EMA, not the raw value.

    signal_delta = max(0, raw_signal - ema_of_signal)

Why: L2's prediction_error has a structural floor even after learning. The
SOM fires a region of 20-40 BMU indices per frequency, and L2 cannot reliably
predict which exact index within a cluster fires next. Before the spatial
soft-match fix, this floor was ~0.97 (binary error: any miss = 1.0). After the
fix (error = spatial distance, not binary), the floor is ~0.35–0.58 depending
on the sequence — still far from zero. Feeding even this 0.40 raw error back
to M54 as a permanent plasticity boost raises eta from 0.13 to ~0.18 and never
lets it fall, preventing the SOM from settling. The delta breaks the cycle: it
is near-zero when error is stable at its floor, and positive only when error
genuinely spikes above that floor.

This applies to ANY future feedback you add:
  - Don't feed raw familiarity back to L2 — it will saturate.
  - Don't feed raw qe_norm back anywhere — it has the same floor problem.
  - Don't feed raw salience back to any lower module — use salience_delta.
  - Always ask: "what is the baseline for this signal?" and use deviation.

The EMA alpha for feedback signals is 0.10 (tau ~10 steps). Do not make it
slower — the feedback stops being selective. Do not make it faster — it chases
step-by-step noise and becomes indistinguishable from the raw signal.

2.  THE SOM IS A REGION MACHINE, NOT A SINGLE-INDEX MACHINE
═══════════════════════════════════════════════════════════════════════════════

M54 with SIGMA_MIN=1.5 deliberately activates a neighbourhood of neurons per
input step. A single input frequency will consistently fire 20-40 different
BMU indices over 300 steps. This is NOT a bug. It is the mechanism that
prevents dead neurons and enables smooth topographic organisation.

Consequences:
  - L2 CANNOT reliably predict the exact next BMU index. Sequence accuracy
    of 30-40% is good. Do not expect 90%+ — that would require a single
    locked BMU per frequency, which would mean dead neurons everywhere else.
  - M55 familiarity is built from the exposure count of each individual BMU,
    not a cluster-level signal. If you want cluster-level familiarity you
    need to aggregate across neighbouring cells yourself.
  - If a future module needs "the frequency right now", use M54's weight
    reconstruction: freq = W[bmu_idx, 0] * (FREQ_MAX - FREQ_MIN) + FREQ_MIN.
    Don't try to infer it from the sequence of BMU indices.
  - If you add a new layer above L2 that needs stable input, consider
    clustering nearby BMU indices into frequency zones first, then feeding
    zone labels rather than raw BMU indices.
  - Attention's attention_gate is built with GATE_SIGMA=1.5 to match M54's
    neighbourhood radius. The gate covers the same spatial extent as the
    SOM's learning region — this is intentional and must be preserved.

3.  CALL ORDER IS NON-NEGOTIABLE
═══════════════════════════════════════════════════════════════════════════════

Every step, the order MUST be:

    1. pred.predict()                  ← prediction BEFORE cortex fires
    2. cortex.step(prediction_error=…, ← M54 fires; delta surprise_signal +
                   familiarity=…)         familiarity LTD suppression fed in
    3. memory.step(curiosity=…,        ← M55 writes, delta fed in
                   rpe_positive=…)        V1 → M55 dopamine boost
    4. memory.recall(bmu_idx)          ← familiarity AFTER cortex fires;
                                          stored for NEXT step's cortex.step()
    5. pred.step(bmu_idx, …,           ← L2 learns from actual BMU +
           prediction_bias=…)             Thought's pre-warming applied
    6a. compute deltas, update EMAs    ← store surprise_signal, curiosity_delta
                                          for NEXT step
    6b. valence.step(prediction_error, ← V1 computes RPE from L2 output;
                     reward)              store pos_rpe for NEXT step's M55
    7. attention.step(…,               ← Attention reads all outputs +
           thought_confidence_delta=…)    Thought suppression applied
    8. thought.step(…)                 ← Thought reads Attention, stores
                                          prediction_bias and confidence_delta
                                          for the NEXT step
    9. action.step(bmu_idx, rpe, …)    ← M56 updates Q from this step's rpe,
                                          selects action for NEXT step

Thought (step 8) is the last thing to run before M56. It reads the
same-step Attention output and stores two signals for the NEXT step:
  - _last_prediction_bias      → passed to pred.step() next step (step 5)
  - _last_confidence_delta     → passed to attention.step() next step (step 7)

Valence (step 6b) runs immediately after L2 (needs prediction_error) and
before Attention (which doesn't use V1 output directly). V1's pos_rpe is
stored and fed to memory.step() on the NEXT step (step 3 of t+1).
Feeding pos_rpe same-step would mean M55 learns from a reward computed
from the same outcome it is currently recording — a temporal loop.

Thought does NOT feed back into anything this step. Moving it earlier
would give it access to stale Attention outputs and create a temporal loop.

Breaking this order produces subtle bugs that are hard to detect:

  - pred.predict() AFTER cortex: prediction uses post-hoc information.
    L2 will appear to learn faster but is cheating — it has seen the answer.
    Accuracy inflates, generalisation is broken.

  - memory.recall() BEFORE cortex: familiarity from the previous BMU gets
    fed to L2 as if it were the current one. The familiarity signal is always
    one step stale.

  - pred.step() BEFORE memory.step(): L2 learns the sequence before M55
    has consolidated the memory. Violates biological ordering.

  - Feedback signals (surprise_signal, curiosity_delta) MUST be from the
    PREVIOUS step. They are computed from l2_out and stored, then fed in on
    the NEXT call. Same-step feedback oscillates or explodes.

  - Attention before steps 1-6: Attention would see the previous step's
    bmu_idx and the current step's surprise_signal — a temporal mismatch
    that corrupts the gate's spatial meaning.

  - Thought before Attention (step 8 before step 7): Thought reads
    attended_bmu from Attention. If Thought runs first, attended_bmu is
    from the PREVIOUS step — Thought would build a prediction bias toward
    last step's focus region, not the current one. Gate suppression would
    also be one step stale.

  - Thought's stored outputs fed same-step: Both _last_prediction_bias and
    _last_confidence_delta are stored by Thought at step t and fed to L2
    and Attention at step t+1. Feeding them same-step would create a loop:
    Attention output → Thought → Attention input, all within one step.

  - valence.step() BEFORE L2: V1 needs prediction_error from pred.step().
    Calling V1 before step 5 uses the PREVIOUS step's error — RPE would
    always be one step stale. V1 must run at 6b (after L2, before Attention).

  - pos_rpe fed same-step to M55: V1's pos_rpe is stored at step t and
    passed to memory.step() at step t+1. Feeding it same-step would mean
    the write-rate boost is computed from the outcome M55 is currently
    recording — the reward signal arrives before the memory is written.

  - familiarity fed same-step to M54: familiarity comes from memory.recall()
    at step 4 and is stored for cortex.step() at step 2 of t+1. Feeding it
    same-step is impossible (recall happens AFTER cortex.step()). Feeding the
    CURRENT step's familiarity to cortex's CURRENT step would require either
    running recall before cortex (stale familiarity, one step offset) or
    a within-step feedback loop that violates the linear call order.

4.  PARAMETER COUPLING — WHAT YOU CANNOT CHANGE IN ISOLATION
═══════════════════════════════════════════════════════════════════════════════

Many parameters are co-tuned. Changing one without the others will break
tests that currently pass. Key couplings:

M54: CONSCIENCE_FACTOR and ETA_BASE
  At ETA_BASE=0.15, CONSCIENCE_FACTOR=0.5 was tuned to prevent catastrophic
  forgetting. If you raise ETA_BASE, you MUST also raise CONSCIENCE_FACTOR.
  Rule of thumb: CONSCIENCE_FACTOR should scale roughly with ETA_BASE.
  The existing BT-09 will catch this if you forget.

M54: FAM_ETA_SUPPRESS and eta floor behaviour
  FAM_ETA_SUPPRESS=1.5 means: at familiarity=0.40 (typical stable mean),
  eta_base drops from 0.129 to ~0.046. At familiarity=0.70 (well-known),
  eta_base drops to ETA_MIN=0.01.
  Without this, eta_base = 0.129 permanently (stability_w=0.85 is a signal
  quality weight, not a familiarity signal — it never falls during learning).
  Keep FAM_ETA_SUPPRESS ≤ 2.0. Above that, ETA_MIN dominates at all times
  and surprise/novelty boosts can no longer lift plasticity meaningfully.
  Keep FAM_ETA_SUPPRESS ≥ 0.5. Below that, the suppression is too weak
  to meaningfully reduce eta at typical familiarity levels.
  The eta formula with all four terms:
    eta = clip(eta_base + eta_curiosity + eta_sequence - eta_familiarity,
               ETA_MIN, ETA_MAX)
  Novelty and surprise boosts still override suppression — a familiar BMU
  that fires in a surprising context (high qe_norm or surprise_signal) will
  still receive elevated plasticity. Suppression is the baseline floor, not
  a hard cap on plasticity.

M54: FAM_ETA_SUPPRESS and M55 DECAY_RATE interaction
  Familiarity from M55 grows slowly (ETA_HEBB=0.04, DECAY_RATE=0.0005).
  At step 150 (BT-34 condition), familiarity is already ~0.46 → eta ~0.04.
  This is intentional: M55 accumulates fast enough that M54 suppression
  takes effect within the first few hundred steps. If you lower DECAY_RATE,
  familiarity persists longer, deepening suppression over time. If you raise
  DECAY_RATE, familiarity decays faster and suppression lifts — M54 stays
  more plastic. Keep the two in sync with the intended memory timescale.

M54: FAM_ETA_SUPPRESS and M54 catastrophic forgetting (BT-09)
  Familiarity suppression makes M54 LESS plastic at familiar patterns, which
  HELPS catastrophic forgetting resistance: overtraining on a new frequency
  suppresses that frequency's neurons faster, protecting older memories.
  No conflict with CONSCIENCE_FACTOR — conscience controls win distribution,
  suppression controls write magnitude. They are independent mechanisms.

L2: CONTEXT_DECAY_BASE and MIN_CONTEXT_TO_LEARN
  CONTEXT_DECAY_BASE=0.30 and MIN_CONTEXT_TO_LEARN=0.50 were tuned together.
  At base=0.30, one step back gives c[prev]=0.70 (above 0.50 threshold).
  Two steps back gives 0.49 (excluded). If you lower base decay, the window
  widens and every past BMU writes to P, making it unselective.

L2: SCORE_TEMPERATURE and curiosity floor
  SCORE_TEMPERATURE=0.15 controls softmax sharpness. At 0.15, the curiosity
  floor after perfect learning is ~0.50. Lower = sharper predictions = lower
  curiosity floor. Higher = softer predictions = curiosity stays high.

Brain: FEEDBACK_EMA_ALPHA and signal selectivity
  At 0.10, the feedback EMA tracks over ~10 steps. The delta surprise_signal
  is ~10× smaller than raw prediction_error during stable periods (BT-31).
  Below 0.05: baseline too slow, stable deltas grow too large.
  Above 0.30: EMA catches up too fast, genuine transitions don't spike.

Attention: GATE_SIGMA and SOM neighbourhood
  GATE_SIGMA=1.5 matches M54's SIGMA_MIN=1.5. These must stay in sync — the
  gate should cover the same spatial extent as the SOM's learning radius.
  If you change M54's SIGMA_MIN, update GATE_SIGMA to match.

Attention: SALIENCE_EMA_ALPHA and responsiveness
  At 0.20 (tau ~5 steps), the EMA is fast enough to track transitions but
  still suppresses single-step noise. Do not go above 0.30 (salience becomes
  indistinguishable from raw). Do not go below 0.05 (too sluggish to gate).

Attention: W_SURPRISE and the salience floor
  W_FAMILIARITY=0.20 means salience has a floor of ~0.20 when familiarity=0.
  This is intentional — completely novel inputs still demand some attention
  even before surprise_signal and qe_norm kick in. If you raise W_FAMILIARITY,
  the salience floor rises and "resting" attention never truly relaxes.

Attention: W_THOUGHT and salience suppression ceiling
  W_THOUGHT=0.15 suppresses salience when Thought is confident.
  Keep W_THOUGHT ≤ W_FAMILIARITY (0.20). If it exceeds W_FAMILIARITY,
  top-down prediction suppresses more than bottom-up familiarity — Thought
  becomes more powerful than recognition, inverting biological priority.
  Maximum combined suppression (full familiarity + full confidence):
  0.35 units off raw salience. surprise_signal (0.50) still dominates.

Thought: PREDICTION_BIAS_STRENGTH and L2 context dominance
  At 0.10, Thought's bias adds ~10% of a full BMU imprint to context.
  Keep ≤ 0.20. Above 0.30, Thought dominates L2's context vector and L2
  stops learning from data — it follows Thought's expectations instead.

Thought: CONFIDENCE_EMA_ALPHA and delta sensitivity
  At 0.15 (tau ~7 steps), tracks learning progress within one frequency
  cycle. Do not go above 0.30 (delta becomes noise). Below 0.05 (too
  sluggish to detect new sequence acquisition).

Valence: RPE_EMA_ALPHA and reward baseline tracking
  At 0.05 (tau ~20 steps), the reward EMA tracks on the same timescale
  as L2's curiosity EMA. This is intentional: both measure "how has L2
  been doing lately" — curiosity tracks error, reward_ema tracks reward.
  Do not raise above 0.15 (EMA chases reward too fast, RPE collapses to
  zero immediately and stops being a learning signal). Do not lower below
  0.02 (EMA too slow, RPE inflates permanently — the same floor problem
  described in Rule 1 but for reward instead of prediction error).

Valence: RPE_M55_BOOST and M55 write rate ceiling
  At 1.0, positive RPE can add up to 1× ETA_HEBB to the write rate,
  on top of CURIOSITY_HEBB_BOOST (also 1.0). Maximum combined boost:
    eta_effective = ETA_HEBB × (1 + 1.0 × curiosity + 1.0 × pos_rpe)
  At full both = ETA_HEBB × 3.0 = 0.12. This is the absolute ceiling.
  Keep RPE_M55_BOOST ≤ 1.0. Above that, RPE dominates over curiosity
  and the intrinsic epistemic signal loses its effect.

Valence: W_EXTERNAL and W_INTRINSIC sum must be ≤ 1.0
  When both are 0.5 (default), total_reward blends both signals.
  Setting W_EXTERNAL > 0.5 and W_INTRINSIC > 0.5 would over-count reward
  and drive reward_ema above the actual signal range, permanently biasing
  RPE negative. The two weights must sum to ≤ 1.0.

5.  ADDING A NEW MODULE — THE CHECKLIST
═══════════════════════════════════════════════════════════════════════════════

If you add M56, M57, L3, Thought, or any new layer:

□  Define it as a standalone class that works WITHOUT Brain.
   It should have default parameter values for any Brain-fed signals (= 0.0).
   Test it standalone first. Only wire it into Brain after it passes its
   own breaktest in isolation.

□  Expose ALL feedback parameters as optional arguments with default 0.0.
   This preserves backward compatibility and lets tests isolate the module.
   Never have a module reach INTO Brain or another module — it only receives
   what Brain passes it.

□  If the new module sends a signal back to any existing module, apply the
   delta rule (Rule 1). Measure the raw signal's floor and ceiling in a real
   pipeline before writing the feedback formula.

□  Add the new module's step counter to BT-03. Add its key outputs to BT-01
   and BT-02. These are the sentinel tests — they catch wiring mistakes early.

□  Test with feedback=0.0 first (BT-20 pattern). Only when the module works
   correctly without feedback should you wire in the feedback and test the
   difference.

□  Write at least one test that proves the feedback signal is SELECTIVE
   (higher at transitions than during stable operation). Without this test
   you will not catch the circular collapse pattern until it's deep in debug.

□  Write isolation tests (BT-38 through BT-41 pattern): verify the new
   module's presence does not change the outputs of any existing module.
   Same seed → deterministic → max_diff must be exactly 0.0.

6.  SIGNAL MEANINGS — DO NOT CONFUSE THESE
═══════════════════════════════════════════════════════════════════════════════

There are now SIX distinct "surprise/novelty" signals. Mixing them up is
the most common conceptual error.

qe_norm (M54)
  "Is this INPUT unfamiliar to the cortex?"
  Measures how different the current input vector is from what M54 has
  learned to represent. Near 0 = the cortex has a good model of this pattern.
  Near 1 = pattern is far from any existing weight vector.
  Changes quickly (EMA alpha=0.01, tau ~100 steps).
  USE FOR: controlling sigma (neighbourhood size), M55 trace window.

familiarity (M55)
  "Has this specific BMU fired before, and how often?"
  Primarily an exposure counter (log scale, saturates at ~200 exposures).
  Supplemented by Hebbian association breadth and recall depth.
  Grows monotonically with repetition, never decreases from experience alone.
  USE FOR: feeding L2 as a recognition prior. Feeding into Attention as
  suppressive signal (high familiarity → lower salience).

prediction_error (L2)
  "Was the sequence transition expected, and how close was the prediction?"
  Spatial soft-match: error = 1 - exp(-dist² / 2σ²) where dist is the
  grid distance between predicted and actual BMU (SPATIAL_SIGMA=2.0).
  At dist=0 (exact match):    error = 0.0
  At dist=1 (adjacent cell):  error ≈ 0.12 — near-correct zone
  At dist=6 (wrong region):   error ≈ 0.96 — full miss
  Further modulated by familiarity: error *= (1 - 0.3 * familiarity).
  Structural floor ~0.35–0.58 after learning (L2 learns the right frequency
  zone but not the exact index within it — the region machine constraint).
  USE FOR: driving curiosity EMA. DO NOT feed raw to M54.

curiosity (L2)
  "Has L2 been consistently wrong lately?"
  EMA of prediction_error (alpha=0.05, tau ~20 steps). With the spatial
  soft-match fix, curiosity meaningfully falls after a sequence is learned
  (drops from ~0.60 early to ~0.30 after training). Before the fix it
  barely moved because prediction_error was stuck at ~0.97 permanently.
  USE FOR: informational read-out. DO NOT feed raw to M55 — use delta.

surprise_signal (Brain)
  "Did prediction_error spike above its recent baseline THIS step?"
  The actual signal fed to M54. Near-zero during stable periods.
  USE FOR: modulating M54 plasticity. Only correct feedback into M54 from L2.

curiosity_delta (Brain)
  "Is curiosity rising right now?"
  The actual signal fed to M55. Near-zero when curiosity is stable.
  USE FOR: modulating M55 write rate. Only correct feedback into M55 from L2.

salience (Attention)
  "How much should the system attend to this moment overall?"
  Weighted combination of surprise_signal, qe_norm, curiosity_delta, and
  (1 - familiarity). Clipped to [0,1]. Smoothed by EMA (alpha=0.20, tau ~5).
  USE FOR: informational signal for Thought or higher layers. Modulating
  how strongly the attention_gate is focused.
  DO NOT feed raw salience back to lower modules — use salience_delta.

salience_delta (Attention)
  "Did salience spike above its recent EMA THIS step?"
  Same delta rule as surprise_signal and curiosity_delta.
  Near-zero when salience is stable. Positive at genuine attention transitions.
  USE FOR: if Attention ever feeds back into lower modules, use this signal.

attention_gate (Attention)
  "Which neurons should be attended to this step?"
  A (64,) probability vector — soft mask over the BMU space.
  Peaks at the current BMU and Gaussian-spreads to neighbours (sigma=1.5).
  Peak height scales with salience: salience=0 → uniform gate.
  USE FOR: Thought or higher layers that want to focus on the attended region
  rather than the full 64-neuron space.

attended_bmu (Attention)
  "Which specific neuron is most salient right now?"
  argmax of attention_gate. At high salience, this equals bmu_idx.
  At low salience, it may wander due to the near-uniform gate.
  USE FOR: quick lookup of the most attended neuron. Check gate_entropy
  first — if entropy is high, attended_bmu is not meaningful.

gate_entropy (Attention)
  "How focused is the attention gate?"
  0 = all weight on one neuron (maximally focused).
  1 = uniform distribution (fully diffuse, no attention).
  USE FOR: deciding whether attended_bmu is meaningful. If entropy > 0.8,
  the gate is essentially uniform and attended_bmu should be ignored.

expected_bmu (Thought)
  "Which cortical neuron does Thought predict will fire NEXT step?"
  argmax of prediction_bias. Meaningful only when focus_entropy is low.
  USE FOR: quick lookup. Check focus_entropy first — if > 0.8, this is noise.

prediction_bias (Thought)
  "What is the probability distribution over next-step BMUs?"
  A (64,) soft distribution built from L2's top_predictions(attended_bmu).
  Sums to 1.0. At cold start: uniform (1/64 each). After learning: peaked
  over the expected next cluster (max ~0.30–0.40).
  USE FOR: fed back to L2 next step to pre-warm context. Also readable by
  any future module that wants to know "where does Thought expect to go?"

thought_confidence (Thought)
  "How concentrated is Thought's prediction? Does it have a clear expectation?"
  max(prediction_bias) - 1/64. Range [0, ~0.95].
  0 = uniform prediction (no idea). ~0.30 = clear cluster expectation.
  IMPORTANT: thought_confidence FALLS as a sequence is learned, not rises.
  When L2 has not yet learned the sequence, P columns are sparse — one strong
  entry per BMU → high max → high confidence. After learning, P distributes
  weight across multiple valid successors → lower max → lower confidence.
  This means confidence is NOT a measure of mastery. It measures how many
  options Thought sees from the current position. High confidence = only one
  known next step. Low confidence = multiple learned transitions available.
  Measured (behaviour test BT-06): confidence 0.486→0.326 as PE 0.40→0.15.
  USE FOR: informational. Readable by higher layers to assess certainty.
  DO NOT interpret rising confidence as "learning is working" — it means
  the opposite. DO NOT feed raw confidence to Attention — use confidence_delta.

confidence_delta (Thought)
  "Did Thought's confidence spike above its recent baseline THIS step?"
  Same delta rule as all other feedback signals. Near-zero when confidence
  is stably high. Positive when Thought suddenly forms a strong prediction.
  USE FOR: fed to Attention next step to suppress salience (predicted events
  are less surprising). If Thought ever feeds other modules, use this.

expectation_error (Thought)
  "Was Thought's PREVIOUS expected_bmu close to what actually fired?"
  Spatial soft-match, same formula as L2: 1 - exp(-dist²/2σ²), σ=2.0.
  Tracks Thought's own prediction accuracy independently of L2.
  Falls from ~0.72 at cold start to ~0.40 after the sequence is learned.
  USE FOR: monitoring Thought's performance. A Thought module that is
  consistently wrong (error stays high) means L2 hasn't learned the sequence.

focus_entropy (Thought)
  "How spread out is Thought's prediction distribution?"
  0 = all mass on one BMU (maximally certain).
  1 = uniform (no idea — cold start or low salience).
  USE FOR: gating expected_bmu. If focus_entropy > 0.8, expected_bmu is
  meaningless and prediction_bias is approximately uniform.

assoc_weight (Thought, v6)
  "What fraction of prediction_bias came from M55 vs L2 this step?"
  0 = pure L2 sequence memory (cold start, no M55 associations formed).
  W_ASSOC_M55 (~0.30) = full blend (M55 has learned associations for this BMU).
  Falls to 0 at low-salience steps where bias falls back to uniform.
  USE FOR: diagnosing how much associative memory is contributing to
  Thought's predictions. Not a feedback signal — informational only.

intrinsic_reward (Valence, v7)
  "How well did L2 predict this step?"
  = 1 - prediction_error. Range [0, 1].
  High = accurate prediction (reward from getting it right).
  Low = failed prediction (no reward).
  This is the system's built-in reward signal — it does not require
  external labels. USE FOR: informational. The raw component of RPE.
  DO NOT feed directly to any module — use rpe or pos_rpe.

total_reward (Valence, v7)
  "What is the combined reward this step (intrinsic + external)?"
  Blend of intrinsic_reward and external reward (if provided).
  When reward=0.0 (default): total_reward = intrinsic_reward exactly.
  When reward=1.0: total_reward = 0.5 × 1.0 + 0.5 × intrinsic_reward.
  USE FOR: informational. The input to the reward EMA.

reward_ema (Valence, v7)
  "What reward level has the system come to expect?"
  EMA of total_reward (alpha=0.05, tau ~20 steps).
  Converges toward intrinsic reward floor ~0.65 with no external reward.
  Rises toward ~0.82+ when consistent reward=1.0 is given.
  USE FOR: baseline for RPE computation. Not a feedback signal directly.

rpe (Valence, v7)
  "Was this outcome better or worse than expected?"
  = total_reward - reward_ema. Range [-1, +1].  SIGNED.
  Positive = better than expected (dopamine burst).
  Negative = worse than expected (dopamine dip/pause).
  Near zero = exactly what was expected (no learning signal needed).
  This is the only signed signal in the stack. All others are [0,1].
  USE FOR: readable by M56 (action layer) as the Q-learning signal.
  DO NOT feed raw rpe to M54 or M55 — high step-to-step variance
  (std ~0.30 even during stable operation) means it fails the delta
  rule test. Use pos_rpe or neg_rpe instead.

pos_rpe (Valence, v7)
  "Was this outcome better than expected?" (positive component only)
  = max(0, rpe). Range [0, 1].
  Non-zero only when total_reward exceeded reward_ema.
  USE FOR: fed to M55 next step to boost Hebbian consolidation.
  "Remember this better — the outcome was good."
  Biologically: dopamine burst → hippocampal LTP.

neg_rpe (Valence, v7)
  "Was this outcome worse than expected?" (negative component, as magnitude)
  = max(0, -rpe). Range [0, 1].
  Non-zero only when total_reward fell below reward_ema.
  USE FOR: informational / diagnostics. Also readable by M56.
  NOT currently wired into any module — M54 plasticity is already
  handled by surprise_signal. Adding neg_rpe to M54 doubles-counts
  (measured: neg_rpe std ~0.30 during stable → same floor problem as raw
  prediction_error). Defer M54 RPE feedback unless specifically needed.

action (M56, v9)
  "Which action should be taken before the next step?"
  Integer in [0, N_ACTIONS). Selected by epsilon-greedy policy over Q table.
  This is the system's output — the only key that directly tells the
  environment what to do. High focus_entropy → random (explore).
  Low focus_entropy + high thought_confidence → argmax Q (exploit).
  USE FOR: pass to environment.step(action) before the next brain.step().

q_values (M56, v9)
  "What is the estimated value of each action in the current BMU state?"
  (N_ACTIONS,) float32 array. Range [-1, +1] per element.
  Q[a] = expected rpe from taking action a in bmu_idx state.
  High Q[a] = action a has been associated with positive RPE in this state.
  USE FOR: inspection, policy analysis, or seeding a higher policy module.

action_epsilon (M56, v9)
  "What was the exploration probability this step?"
  = EPSILON_MIN + (EPSILON_MAX - EPSILON_MIN) * focus_entropy
    * (1 - CONFIDENCE_GATE * thought_confidence)
  Range [EPSILON_MIN, EPSILON_MAX] = [0.05, 0.50].
  USE FOR: monitoring exploration vs exploitation trade-off.
  DO NOT feed back to any other module — it is a decision parameter,
  not a learning signal.

q_mean (M56, v9)
  "How much has M56 learned overall?"
  Mean absolute Q value across the entire 64 × N_ACTIONS table.
  Near zero at cold start. Grows as Q accumulates RPE signal.
  USE FOR: monitoring M56 learning progress.

7.  KNOWN ARCHITECTURAL GAPS (NOT BUGS — DELIBERATE LIMITATIONS)
═══════════════════════════════════════════════════════════════════════════════

CLOSED GAPS (implemented, no longer pending)
--------------------------------------------
L2 cluster-blindness — CLOSED
  Replaced binary error with spatial soft-match:
    error = 1 - exp(-dist² / 2 × SPATIAL_SIGMA²)
  Error floor dropped from ~0.97 → ~0.35–0.58. Curiosity now meaningfully
  falls after learning. All delta signals above L2 are cleaner as a result.

familiarity → L2 modulation — CLOSED
  familiarity now scales down prediction_error:
    error *= (1 - FAMILIARITY_ERROR_SCALE * familiarity)
  Familiar sequences produce less prediction surprise, which causes curiosity
  to fall faster on well-known material. Biologically: hippocampal familiarity
  suppresses prefrontal prediction error signals.

Top-down attention — CLOSED
  Thought provides top-down salience suppression via confidence_delta →
  Attention (W_THOUGHT=0.15 suppressive weight), and top-down context
  pre-warming via prediction_bias → L2 (PREDICTION_BIAS_STRENGTH=0.10).
  The PFC→thalamus and PFC→striatum pathways are both implemented.

M55 recall wired into Thought (v6) — CLOSED
  Thought's prediction_bias is now a 70/30 blend of L2 sequence memory
  (temporal: "what fires next in sequence") and M55 associative memory
  (Hebbian co-occurrence: "what tends to co-fire with this BMU").
  Implemented in thought.py using a direct W[attended_bmu] row lookup —
  not a full recall settling loop, just a fast weight read. New output
  key assoc_weight reports the M55 fraction each step. New parameters:
  W_ASSOC_L2=0.70, W_ASSOC_M55=0.30, MIN_ASSOC_STRENGTH=1e-4.
  Biologically: hippocampal CA3→CA1 pattern completion feeding PFC
  top-down prediction circuits alongside basal ganglia sequence memory.

M55 → M54 familiarity LTD suppression (v8) — CLOSED
  M54's eta_base was permanently elevated at ~0.129 during stable operation
  because stability_w=0.85 is a signal quality weight (not a learning progress
  signal) and never falls after learning. This kept M54 in moderate-plasticity
  state permanently, rewriting well-learned weights unnecessarily.
  Fix: familiarity from M55 recall is stored at step t and passed to
  cortex.step() at step t+1 as a suppressive term:
    eta_familiarity = FAM_ETA_SUPPRESS × (ETA_BASE - ETA_MIN) × familiarity
    eta = clip(eta_base + eta_curiosity + eta_sequence - eta_familiarity,
               ETA_MIN, ETA_MAX)
  At typical stable familiarity (0.40), eta drops from 0.129 to 0.040.
  At high familiarity (0.70), eta reaches ETA_MIN=0.01.
  Novelty and surprise boosts still override suppression at transitions.
  Selectivity (novel/stable) improved from ~1.4x to ~2.4x.
  Biologically: perirhinal cortex LTD modulation of primary cortex plasticity —
  synapses for well-represented patterns are stabilised and resist further change.

neg_rpe → M54 gap — CLOSED BY ANALYSIS (not implemented — deliberately dropped)
  The original gap proposed wiring neg_rpe to M54 for "disappointment-driven
  plasticity." Full analysis showed: this is not needed and would be harmful.
  (1) neg_rpe std ~0.30 during stable operation → same floor problem as raw
      prediction_error. A second EMA baseline reduces stable floor to 0.075
      but selectivity is only 0.59x (transitions LOWER than stable — backwards).
  (2) surprise_signal already handles the same biological pathway more cleanly.
  (3) The real M54 problem was the persistent eta floor, now fixed via familiarity
      suppression which is more principled and more selective.
  This gap is closed by analysis: the proposed fix was wrong. The correct fix
  (familiarity LTD suppression) was identified and implemented instead.
  New module valence.py (Valence class) computes reward prediction error:
    rpe = total_reward - reward_ema
    total_reward = intrinsic_reward (1 - prediction_error) when no external reward
    total_reward = 0.5×external + 0.5×intrinsic when external reward provided
  pos_rpe (positive RPE) is fed to M55 next step to boost Hebbian write rate:
    eta_effective = ETA_HEBB × (1 + curiosity_boost + RPE_M55_BOOST × pos_rpe)
  RPE is SIGNED [-1, +1] — the only signed signal in the stack.
  V1 runs at step 6b (after L2, before Attention). pos_rpe fed next-step.
  V1 does NOT feed M54 (neg_rpe std ~0.30 stable → fails delta rule test).
  rpe output available for M56 (action layer) Q-learning signal.
  Biologically: VTA/substantia nigra dopamine — consolidation boost on
  positive RPE, action learning signal for basal ganglia.

OPEN GAPS (deliberate deferral)
--------------------------------
Attention → lower modules (not implemented)
  Attention has no feedback path into M54, M55, or L2.
  Future: salience_delta could modulate M54's eta, or attention_gate could
  weight M55's Hebbian update (attended neurons form stronger associations).
  If you implement this, use salience_delta — not raw salience — and measure
  the floor before designing the formula (Rule 1).

M56 — Action / motor output layer — CLOSED (v9)
  Implemented in m56_action.py as ActionLayer.
  State space: 64 BMU indices. Action space: N_ACTIONS=4 (configurable).
  Learning: TD(λ) — Q[s,a] += ETA_Q * rpe * e[s,a], where e is an eligibility
  trace that decays at TRACE_DECAY=0.20 per step (τ ~5 steps).
  Exploration: epsilon-greedy with adaptive epsilon:
    base_epsilon = EPSILON_MIN + (EPSILON_MAX - EPSILON_MIN) * focus_entropy
    epsilon      = base_epsilon * (1 - CONFIDENCE_GATE * thought_confidence)
  High focus_entropy → explore. High thought_confidence → exploit.
  Q values bounded in [-1, +1] to match rpe range.
  Runs at step 9 (last): updates Q from this step's rpe then selects
  the action for the NEXT step. Same next-step action pattern as all
  other stored signals.
  Output key 'action' = action index to execute before the next brain.step().
  Biologically: cortico-striatal TD(λ) with locus coeruleus NE exploration.
  Parameters: ETA_Q=0.05, Q_DECAY=0.001, TRACE_DECAY=0.20,
              EPSILON_MIN=0.05, EPSILON_MAX=0.50, CONFIDENCE_GATE=0.30.

neg_rpe → M54 (not implemented, deliberately deferred)
  Negative RPE (worse than expected) could increase M54 cortical plasticity:
  "Something bad happened unexpectedly — update the cortex."
  NOT implemented because neg_rpe std ~0.30 during stable operation fails
  the delta rule test (same floor problem as raw prediction_error). If you
  attempt this, apply a second EMA baseline to neg_rpe before feeding M54,
  and verify with measurements that the stable floor drops below 0.05.

Reward penetration into familiarity is weak (open — ET-03)
  External reward modulates M55's Hebbian write STRENGTH (via pos_rpe →
  η_eff) but does not change whether M55 writes at all. The write decision
  is gated by perceptual novelty (qe_norm, curiosity_delta) — two brains
  seeing identical input make identical write decisions regardless of reward
  level, producing identical write counts and near-identical familiarity.
  Measured: 800 steps, reward=1.0 vs reward=0.0. Write count: 499 vs 499.
  Familiarity at steps 50–150: 0.4783 vs 0.4783 — indistinguishable.
  total_reward and pos_rpe diverge correctly in the early phase (steps 0–80),
  confirming the reward pathway itself is wired correctly. The gap is that
  pos_rpe's influence on η_eff does not translate into detectable familiarity
  change because familiarity is dominated by the exposure counter, not write
  magnitude. If you need reward to accelerate recognition (e.g. an agent that
  should prioritise rewarded stimuli for faster familiarisation), you must gate
  the WRITE DECISION on pos_rpe, not just the write magnitude. Until then,
  reward affects memory consolidation depth, not recognition speed.

Salience is a binary novelty detector, not a graded distance measure (open — ET-04)
  The attention salience signal saturates at the same level for any input the
  brain has not seen before, regardless of how different it is from the prior.
  Measured: after 200 steps on 0.5 Hz, both a small step (0.5→0.7 Hz, gap=0.2)
  and a large jump (0.5→2.0 Hz, gap=1.5) spiked salience to ~0.544 — ratio 1.00x.
  The mechanism: salience = f(surprise_signal, qe_norm, curiosity_delta, familiarity).
  All four inputs saturate at the same level for any "completely unseen" input.
  The brain can distinguish familiar from novel, but cannot distinguish "slightly
  different" from "very different" within the novel category.
  This is not harmful for the current stack — no downstream module uses a graded
  distance signal. It would become a problem for M57 planning if salience is used
  as a proxy for "how far is the current state from where I expect to be." A large
  deviation and a small deviation would trigger identical planning urgency.
  If you need graded distance in salience, the fix is to incorporate the spatial
  distance between current BMU and the previous attended BMU directly into the
  salience formula, rather than relying on familiarity/surprise saturation.

No temporal integration across sessions
  All modules reset between Brain() instantiations. M54 weights, M55's W
  matrix, L2's P matrix, Attention's EMA state, Valence's reward_ema, and
  Brain's EMA state all need to be saved and restored together. Restoring
  only some produces inconsistent behaviour. Defer until approaching deployment.

8.  TEST SUITE RULES — KEEPING THE BREAKTEST HONEST
═══════════════════════════════════════════════════════════════════════════════

The breaktest exists to catch regressions. Keep it honest:

DO NOT lower a threshold just to make a test pass on your machine.
  Before changing any threshold, measure the actual signal across ≥5 seeds
  on ≥2 platforms (ARM Mac and x86 Linux at minimum). The threshold should
  be below the minimum measured value with a 20% safety margin.

DO NOT skip a failing test by setting warn=True when it should be a FAIL.
  warn= means "this is borderline and we accept it temporarily".
  If the signal is wrong, make it FAIL so it forces a fix.

DO NOT change test semantics when porting to a new version.
  BT-07 was changed from "< 10% dead neurons" to "Brain wiring doesn't
  increase dead count vs standalone". The original intent was the latter —
  it was misdocumented. When a test fails in a new version, check whether
  the test is measuring what it claims before adjusting thresholds.

Tests that are X-platform sensitive (BT-05, BT-09):
  Thresholds calibrated on both ARM and x86:
    BT-05 sigma diff:     > 0.035  (measured min ~0.044)
    BT-09 freq error:     < 0.25   (measured max ~0.21)

When adding a new module, add tests in this order:
  1. Output key completeness (BT-01 / BT-35 pattern)
  2. Signal bounds (BT-02 / BT-36 pattern)
  3. Step counter (BT-03 / BT-37 pattern)
  4. Backward compatibility — feedback=0.0 matches old behaviour (BT-20 pattern)
  5. Isolation — new module doesn't change any existing module's outputs
     (BT-38/39/40/41 pattern — same seed → deterministic → max_diff == 0.0)
  6. Selectivity — signal is higher at transitions than stable (BT-42/43 pattern)
  7. Spatial correctness — gate/spatial outputs track the right neuron (BT-44 pattern)

Isolation tests (BT-38 through BT-41) are the most important new pattern.
Two Brain instances with the same seed must produce byte-identical outputs
for all existing keys when the new module is added. If they diverge, the
new module is modifying shared state or changing call order.

10. THE ONE-LINE SUMMARY OF EVERY MISTAKE WE MADE
═══════════════════════════════════════════════════════════════════════════════

1.  Fed raw signals as feedback → use deltas.
2.  Tuned M54 parameters in isolation, then broke them with feedback → test
    the integrated system, not just the standalone module.
3.  Assumed L2 would produce low error after learning → it structurally
    cannot with a region-firing SOM. Measure your signal floors before
    designing formulas that depend on them being low.
4.  Wrote tests that passed on one platform but not another → calibrate
    thresholds with measurements from both ARM and x86.
5.  Wrote tests that expected behaviour the architecture intentionally
    does not have (unique BMU convergence) → understand what each module
    is designed to do before writing the assertion.
6.  Tried to fix a logic bug by adjusting a test threshold → if the test
    is catching a real problem, fix the problem.
7.  Wired the feedback signal BEFORE verifying the module worked correctly
    without it → always build and test standalone first, then integrate.
8.  Applied Gaussian spread to the attention gate regardless of salience →
    gate was always peaked even at zero salience. Fix: scale Gaussian boost
    by salience so zero-salience produces a truly uniform (maximum entropy) gate.
9.  Tested salience falling monotonically over time → Brain's surprise_signal
    re-spikes every ~100 steps even on constant input (SOM drift). Cannot
    measure monotonic fall. Test the mechanism instead: at matched surprise
    levels, high-familiarity steps produce lower salience than low-familiarity.
10. Copied a test's description without understanding its original intent →
    BT-07 said "< 10% dead" but the original test compared Brain vs standalone.
    When porting tests to a new version, re-read the original implementation,
    not just the docstring.
11. Wrote the context decay direction wrong in BT-15 → high prediction error
    produces LOWER decay (longer window), not higher. decay = BASE - MOD*error.
    The formula is in the code — read it before writing the test assertion.
12. Documented two gaps as open when they were already implemented → L2
    cluster-blindness and familiarity→L2 were both coded before the guide was
    written. Always check the actual source before listing something as a gap.
    A gap in the guide that is closed in the code is a lie that misleads future
    developers into thinking they need to build something that already exists.
13. Not all top-down signals need the delta rule → prediction_bias is a
    direction vector (sums to 1.0), not a scalar with a floor problem. The
    delta rule applies to scalar signals that have an inflated absolute baseline
    (prediction_error floors at ~0.40, curiosity floors at ~0.30). A probability
    vector that is already relative (deviation from uniform) does not need an
    EMA baseline subtracted — applying delta to it would make no sense.
14. RPE is already a delta — do not apply the delta rule twice → RPE is defined
    as (actual - expected), which makes it a deviation by construction. Unlike
    prediction_error which has a structural floor that needs the delta rule, RPE
    already oscillates around zero. Subtracting a second EMA from RPE would give
    the acceleration of the reward signal, not the signal itself.
15. Measured neg_rpe before deciding not to wire it into M54 → neg_rpe has
    std ~0.30 during stable operation (same floor problem as raw prediction_error).
    Do not wire any RPE derivative to M54 without first verifying that its
    stable floor drops below 0.05 after a second EMA baseline is applied.
    M54 plasticity is already well-served by surprise_signal.
16. Wrote BT-67 (pos_rpe rises with reward) against a pre-warmed brain →
    after 100 warmup steps with reward=0.0, reward_ema rises to ~0.78 (high
    because intrinsic_reward approaches 1.0 on familiar steps). Switching to
    reward=1.0 gives total_reward ~0.85 which is still below 0.78 ema → pos_rpe
    stayed zero. Fix: test pos_rpe from cold start (ema=0.5) where reward=1.0
    reliably produces positive RPE. Always check what reward_ema will be before
    writing a test that depends on pos_rpe being non-zero.
17. M55's W row read in Thought is not a recall — it is a direct weight lookup.
    Calling memory.recall() inside Thought would trigger a full settling loop
    (up to 10 iterations) on every Brain step, doubling M55 computational cost.
    Instead, Thought reads memory._W[attended_bmu] directly. This is a read-only
    fast path that does not trigger settle, does not advance memory.t, and has
    no side effects on M55 state. The distinction matters: recall() and _W lookup
    serve different purposes — recall() for full pattern completion, _W lookup
    for the association strengths that feed prediction_bias.
18. The M54 persistent eta floor was caused by the wrong signal being blamed.
    The gap was documented as "neg_rpe → M54 for disappointment plasticity."
    Measurements showed neg_rpe has 0.59x selectivity at transitions (LOWER
    than stable) — feeding it to M54 would make plasticity ANTI-selective.
    The real problem was that stability_w=0.85 is a signal quality weight that
    never falls after learning, keeping eta_base at 0.129 permanently.
    The correct fix was familiarity LTD suppression from M55. Always measure
    what is actually driving the problem signal before proposing a fix — the
    component you blame may not be the root cause.
19. FAM_ETA_SUPPRESS was set too high (1.5), causing three test failures.
    At typical stable familiarity (~0.78), eta_familiarity = 1.5 × 0.14 × 0.78
    = 0.164, which exceeds ETA_BASE=0.15 entirely — eta was permanently floored
    at ETA_MIN=0.01. This made ALL neurons almost stop learning, including
    rarely-visited ones, causing (a) more dead neurons than standalone M54,
    (b) incorrect BT-20 premise (Brain never matches standalone post-v8 because
    familiarity is always wired in), and (c) inflated pass-1 accuracy in BT-30
    from BMUs clustering near the origin.
    Fix: FAM_ETA_SUPPRESS lowered from 1.5 to 0.5. The guide said "keep ≤ 2.0"
    but the real constraint is: at your TYPICAL stable familiarity, eta_fam
    must not exceed (ETA_BASE - ETA_MIN). Calculate before choosing the value.
    BT-20 was also rewritten: the old premise "Brain with no feedback = standalone
    M54" became stale the moment familiarity was permanently wired into M54.
    Replace such tests with the actual intent (determinism) not a stale proxy.
20. BT-30's convergence test was measuring SOM differentiation, not P learning.
    Without warmup, all 4 frequencies land on one dominant BMU (SOM not yet
    separated). P correctly predicts that BMU → inflated pass-1 accuracy. SOM
    then differentiates in passes 2/3, breaking the mapping → accuracy collapses.
    Fix: 500-step warmup before the 3-pass measurement. Always ask: "has the
    lower module (SOM) finished learning before I measure the upper module (P)?"
    Any convergence test on a higher layer must warm up all lower layers first.
21. BT-74's ratio threshold (1.5x) was platform-specific. On ARM Mac, numpy RNG
    produces different BMU visit patterns → lower familiarity accumulation →
    less LTD suppression → higher stable eta → smaller novel/stable ratio (1.44x
    vs 4.3x on x86). The direction (novel > stable) was correct on both platforms.
    Only the threshold failed. Fix: lower to 1.3x (10% margin below ARM minimum).
    General rule: for ratio tests, always measure the minimum across ALL target
    platforms before setting the threshold. The guide section 8 already says
    "calibrate on both ARM and x86" — this was a failure to apply that rule.
22. Tested reward's effect on familiarity at convergence instead of at cold start →
    By step 600, intrinsic_reward (1-PE) dominates total_reward for both rewarded
    and unrewarded brains (PE drops to ~0.05 on familiar input → intrinsic ~0.95).
    External reward=1.0 adds only 0.025 on top of that, and reward_ema catches up
    immediately → pos_rpe collapses to near-zero in both conditions. Familiarity
    was measured at steps 600–800 — long after convergence — and showed no
    difference. The correct test window is steps 0–80 (cold start), where reward_ema
    is still at 0.50 and reward=1.0 genuinely produces pos_rpe ~0.016 vs 0.0.
    Always check what reward_ema will be at the measurement window before writing
    a test that depends on pos_rpe being non-zero. See also mistake 16.
23. Designed ET-04 (gradual vs sudden transition) to compare max-of-N-spikes vs
    max-of-1-spike, then declared the test a design failure when gradual won.
    The gradual path steps through 7 frequency transitions (0.5→0.7→0.9→...→2.0),
    each producing a separate salience spike. max(gradual) = max of 7 spikes.
    The sudden path produces 1 spike. max(sudden) = max of 1 spike.
    Gradual wins by construction, which is the wrong comparison.
    The correct framing: compare the FIRST single transition in each path at the
    same moment after identical warm-up. When compared correctly (0.5→0.7 vs
    0.5→2.0), the spikes are nearly identical (0.5445 vs 0.5447), revealing
    Finding 2 (salience is a binary detector). If the original test had been
    designed correctly, Finding 2 would have been discovered directly rather
    than via the incorrect design's failure. When designing contrastive tests,
    ensure the two conditions differ on exactly one variable — not on the number
    of events that accumulate in the measured signal.

M57 PLANNER — MENTAL SIMULATION AND LOOK-AHEAD  (v10)
═══════════════════════════════════════════════════════════════════════════════

Added in v10. File: m57_planner.py (Planner class).
Runs at step 10 — after M56 (the last module in the stack).
Brain breaktest updated to v10: 63 existing tests retained + 9 new (BT-96–BT-104).

WHAT IT DOES
------------
M57 is the deliberative layer. Every module below it perceives, predicts,
remembers, attends, and reacts reflexively. M57 thinks before acting.

Each step, it runs a look-ahead tree PLANNING_DEPTH=3 steps forward over all
N_ACTIONS=4 candidate actions. It uses L2's sequence predictions (read-only)
to simulate future BMU states and scores each imagined trajectory using
Valence's reward baseline (discounted by GAMMA=0.85 per step).

The action with the highest discounted simulated value is the PLANNED action.
M57 overrides M56's habit action only when planning_weight > PLANNING_GATE_THRESH.

CALL ORDER
----------
Added as step 10:
    10. planner.step(bmu_idx, pred, valence, memory, m56_out, ...)
        ← simulates 3-step tree READ-ONLY
        ← returns final_action (= M56 action when planning_weight ≤ threshold)

Brain's 'action' key is now M57's final_action.
New 'habit_action' key = M56's raw Q-selected action (for diagnostics).
All other Brain output keys are unchanged.

THE MOST CRITICAL RULE: READ-ONLY SIMULATION
---------------------------------------------
M57 MUST NOT modify any module's internal state during simulation.
This is verified by BT-101 and BT-102. Violations produce hallucination-driven
learning: the brain learns from imagined events as strongly as real ones.

M57 reads from:
  - pred._P and pred.top_predictions()  — L2 sequence memory (read-only lookup)
  - valence._reward_ema                  — reward baseline scalar (read-only)
  - memory._W                            — M55 associations (read-only row lookup)

M57 NEVER calls:
  - cortex.step()   — would rewrite SOM weights
  - memory.step()   — would write Hebbian associations
  - pred.step()     — would update sequence probabilities
  - valence.step()  — would shift the reward baseline

PLANNING GATE AND SIGNAL CALIBRATION
--------------------------------------
planning_weight = PLANNING_WEIGHT_BASE × thought_confidence
                  × (1 - focus_entropy) × salience

CALIBRATED TO REAL BRAIN SIGNALS — do not use test-harness values.
Measured in trained Brain (500 steps, constant freq):
  thought_confidence:  ~0.18–0.20  (max, not typical)
  focus_entropy:       ~0.63–0.67  (stable operation)
  salience:            ~0.10–0.26  (stable operation)

At typical trained values:  planning_weight ≈ 0.006–0.015
At high-salience transitions: planning_weight ≈ 0.030–0.060

PLANNING_GATE_THRESH = 0.005  (calibrated — see Rule 22 below)

This was the key lesson: the threshold in the standalone breaktest was 0.35
(calibrated against forced signals of 0.9/0.9/0.9). Real Brain signals are
~20× smaller. Always measure actual signal ranges before setting thresholds.

HOW ACTIONS DIFFERENTIATE TRAJECTORIES
-----------------------------------------
Actions don't teleport to random BMUs — they select among L2's top-K
predictions, biased by grid direction (up/right/down/left).

At first simulation step (depth=0): each action scores L2's top-K predictions
by alignment with its grid direction vector. The prediction best-aligned with
the action's direction is chosen. This guarantees different actions lead to
different simulated first-step BMUs — without which all sim_values would be
identical and planning would always agree with M56.

At deeper steps (depth>0): pure L2 sequence prediction, no action influence.
The action is committed at depth=0; the trajectory then follows what L2 has
learned about where the SOM goes from there.

PFC/HABIT SWITCHING
--------------------
M57 does not replace M56 — it overrides M56 when planning is reliable.

planning_active = True  when planning_weight > PLANNING_GATE_THRESH
                         → Brain is attentive, focused, Thought has confidence
                         → deliberate choice overrides habit

planning_active = False when weight ≤ threshold (cold start, novel input,
                          diffuse attention) → M56's Q-selected habit takes over

Biologically: prefrontal cortex deliberation overrides striatal (BG) habit
when the PFC has a clear model of the situation. Novel/uncertain states
revert to habit (BG). M57 implements this switching.

NEW OUTPUT KEYS (v10)
----------------------
action               int          — FINAL action (M57 or M56 depending on gate)
habit_action         int          — M56's raw habit action (diagnostic)
planned_action       int          — M57's preferred action from simulation
planning_weight      float [0,1]  — confidence × focus × salience
planning_active      bool         — True if M57 overrode M56 this step
sim_values           ndarray(4,)  — discounted value per action from look-ahead
sim_depth            int [0,3]    — look-ahead depth reached
plan_vs_habit_delta  float        — sim_values[planned] - Q[habit_action]
                                    positive = planning found better than habit

PARAMETERS (m57_planner.py)
-----------------------------
PLANNING_DEPTH        = 3      — look-ahead steps (beyond 3: uncertainty compounds)
GAMMA                 = 0.85   — future discount per step
PLANNING_WEIGHT_BASE  = 1.0    — scales the planning_weight formula
PLANNING_GATE_THRESH  = 0.005  — CALIBRATED TO REAL SIGNALS (see above)
SIM_TOP_K             = 3      — top-K L2 predictions per simulated step
ACTION_BMU_INFLUENCE  = 0.20   — how much actions bias the first simulated step
SCORE_FAMILIARITY_WEIGHT = 0.20  — familiarity bonus in state scoring

KNOWN OPEN GAPS (v10)
-----------------------
No multi-frequency planning
  M57 only simulates from the current BMU. It does not simulate across
  different input conditions. A future M58 could run multi-context planning.

No action→reward learning in simulation
  M57's scoring uses L2 confidence and M55 familiarity as proxies for reward.
  It does not use M56's Q-values to score simulated states (which would be
  more accurate but risks circular dependency — Q values were learned from
  the same M57-influenced actions). A future version could blend both.

No persistence
  All M57 state (sim_values history, planning rate) resets on Brain()
  instantiation. Must be saved/restored as part of full state persistence
  (the broader open gap listed in section 7).

RULE 22 APPENDED TO SECTION 10 — LESSON FROM M57
═══════════════════════════════════════════════════════════════════════════════

22. Gate thresholds must be calibrated to REAL signal magnitudes, not
    test-harness extremes. M57's standalone breaktest forced thought_confidence=
    0.9, focus_entropy=0.1, salience=0.9 → planning_weight = 0.729 → threshold
    of 0.35 seemed reasonable. In real Brain operation, the same signals produce
    planning_weight ~0.006–0.016 (20× lower). Setting threshold=0.35 meant
    planning NEVER engaged. Fix: measure actual signal ranges in a trained Brain
    BEFORE writing the threshold, then set threshold to ~30–50% of the observed
    peak. The standalone breaktest is a functional test (does it work at all?),
    not a calibration source. The integrated system is the calibration source.

WHY THIS CHANGE MATTERS
───────────────────────
PLV vectors are re-normalized every step (top_plv / top_plv.max). This means
the 20 PLV dimensions contribute effectively random noise relative to
frequency — they carry per-step phase structure, not a stable frequency
signal.

In M54:  1 freq dim vs 20 PLV dims = PLV noise dominated BMU competition.
         The SOM was clustering noise, not frequency. Adjacent frequency
         input vectors were only 0.11 apart in 23D space.

In M55:  8 freq dims vs 20 PLV dims = frequency clearly dominates.
         Adjacent frequency input vectors are 0.32 apart in 30D space (2.83×).
         The SOM now has enough signal to build a real frequency map.

═══════════════════════════════════════════════════════════════════════════════
WHAT IS STILL NOT FIXED IN M55
═══════════════════════════════════════════════════════════════════════════════

The previous session proposed three fixes; M55 implements a different
(and effective) fourth fix but left the first three unaddressed:

1. SIGMA_MIN = 1.5  (still present, not reduced to 0.6)
   ──────────────────────────────────────────────────────
   h(d=1) = exp(−1/(2×1.5²)) = 0.80
   Every update bleeds 80% into the adjacent grid row.
   Over 50k longrun steps, this still risks pulling distant frequency
   clusters toward each other when one frequency dominates the grammar
   for extended periods. The 2.83× better input separation in M55 helps
   resist this, but doesn't eliminate it — especially for grammar-heavy
   patterns where one transition fires repeatedly.

2. FAM_ETA_SUPPRESS = 0.5  (still present, not zeroed)
   ──────────────────────────────────────────────────────
   At familiarity=0.6 (reached by step ~3000):
     eta effective ≈ ETA_MIN + (ETA_BASE − ETA_MIN)×0.8 − 0.5×0.14×0.6 = 0.087
   At familiarity=0.8 (longrun steady state):
     eta effective ≈ 0.073
   This is low but non-zero. Risk is moderate — M55's better input
   separation means the map doesn't NEED as much plasticity to stay
   organized, but at 50k steps the suppression may still cause the map
   to freeze before rare frequencies (A=0.5, H=2.0) are fully consolidated.

3. No spread initialization
   ──────────────────────────────────────────────────────
   All neurons still initialize with uniform random weights (~N(0.5, 0.17)).
   A=0.5 Hz and H=2.0 Hz are visited with low probability by the grammar
   (A starts 12.5% of transitions, H visited ~10%). Without initialization
   pre-placing some neurons near freq_norm=0.0 and freq_norm=1.0, the map
   must discover these extremes by random drift — which is slow.

SEVERITY ASSESSMENT:
  With the freq_repeat fix, the risks above are REDUCED but not eliminated.
  For the 30k-step probe, M55 achieves 7.0/8 unique BMUs — good but not
  reliably 8/8. At 50k steps with the actual grammar distribution, seed
  variance could produce a run where A and H share BMUs.
